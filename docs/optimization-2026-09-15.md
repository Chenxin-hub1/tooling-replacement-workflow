# 经用户授权的优化（2026-09-15）

桌面继续使用指定样板的 HTML/CSS；未重做视觉设计。原文件留作基准。下面是用户确认后的变更，不再宣称所有文案与行为完全不变。

## 已实现

- Today 使用当前本地日历日期；跨天刷新状态，正在编辑的表单不被重绘。新项目独立保存创建日期，不随 Today 变化。
- PEND/TBD/NA 等未确认值不能把动作标为完成；明确选项 Not applicable 仍可正常完成。实际完成日期必须有效且不晚于今天。
- 长依赖链按拓扑顺序排期，服务端拒绝缺失依赖和循环；未完成项目的进度不会四舍五入成 100%。Lead time 与提醒间隔经过校验，逾期重复间隔不可为 0。
- 新项目编号查找未占用序号，删除项目后不会因项目数量变化产生重复编号。
- 移除延迟抢焦点，避免快速录入备注时文字进入结果字段。
- 邮件/Teams 保留规则、自动/手动预览，按钮和提示明确未发送；没有接通外部发送。
- 服务器写入响应丢失后，同内容重试不重复更新、不误报版本冲突。不同内容的过期写入继续返回 409。未确认保存的内容保留在当前浏览器标签页对应的本地备份中，可从 Admin 下载恢复。
- 手机端表格在卡片内部滚动，窄屏表单改为单列、按钮可触控；桌面 CSS 没有重排。

## Excel

同一 Upload Excel 入口增加预览，确认前不改当前工作区。预览列出新建/更新数量、缺失值、重复标识、未知选项、混合日期和待核对列。

支持真实表中可以明确对应的 Part No、Description、Old Supplier、ZF Tool PO、Savings Anual Estimated、Coverage、TIER 2 SOP、Change Internal / External 等。未区分的 BPW、CVS CR、OEM - Tech 不猜对应类型，保留原文。

没有 Project ID 时，根据零件号、工具标签、穴数、PPAP ID 和 TOOL ID 生成可重复的标识；重复身份阻止导入。后续应保留导出的 Project ID；若身份字段发生变化，应提供已知 Project ID，不能把它当成同一条记录自动覆盖。

缺少/歧义创建日期会阻止正式导入，只有明确提供确认日期才可继续。缺少负责人保持未分配，不填演示人员。导入项目的详情中保留原始表头、值和核对提示，包括两个重复 Status 列。工作区 JSON 也包含这些来源信息。

纯目标日期仅录入目标值，不假设实际完成；Completed 加明确且不在未来的日期才作为有日期的完成记录。含多个日期、未知日期格式或缺少实际结果的 Completed 留待核对。明确编号/合法选项的导入表示今天录入该字段，不推断真实历史审批日期。

## 本轮暂不启用

用户明确暂不需要登录/账号管理；保留现有人员选择，不能视为身份认证。后续接入位置是 `backend/app/api/workspace.py` 的访问依赖及前端 who 区域，需届时确定本地账号或公司统一登录。

邮件/Teams 尚未决定是否启用。现有提醒计算和预览保留在样板函数中，未来可接独立投递服务；当前无任务队列、邮件凭据或发送调用，不存在假装已发送的后端接口。

真实 Excel 仅只读核对，没有导入、复制入仓库或上传。用户已同意歧义保留待核对。因创建日期等尚未确认，继续使用 6 个样板示例项目。当前只在本机运行，暂不上传 Git。
